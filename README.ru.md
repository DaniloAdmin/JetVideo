# JetVideo — Automatic Video Publisher

[English](README.md) · [Українська](README.uk.md) · [Русский](README.ru.md)

JetVideo нарезает видео на части, добавляет баннеры и планирует публикации в TikTok. Монтаж работает локально через FFmpeg. Публикации используют ваш аккаунт Buffer и хранилище Cloudflare R2.

## Быстрый старт

**Нарезать видео.** Откройте «Монтаж и нарезка» и нажмите «Добавить видео». В режиме «Нарезать на части» для двухминутных роликов оставьте `00:02:00` и `часть {part}`. Укажите папку результата и нажмите «Начать нарезку».

**Запланировать первую публикацию.** Создайте [ключ Buffer](docs/BUFFER_SETUP.ru.md) и [хранилище Cloudflare R2](docs/R2_SETUP.ru.md). В JetVideo сохраните данные в **Публикации → Подключения**, привяжите TikTok-канал в **Аккаунтах** и нажмите **Проверить подключения**. Затем добавьте один ролик на **Главной** и откройте **Предпросмотр**.

Нажмите значок **глобуса** в правом верхнем углу, чтобы сменить язык. JetVideo запомнит ваш выбор. Нажмите **?** или **F1**, чтобы открыть это руководство. Список вверху окна позволяет перейти к нужному разделу.

## Возможности

- Несколько TikTok-профилей в одном окне: свои папки, расписания, очередь и история; общие подключения Buffer/R2. Удаление профиля убирает его из списка, сохраняя все файлы и публикации в Buffer.
- MP4, MOV и WebM с произвольными именами. Старые `181.mp4` и `181_with_ad.mp4` сохраняют номер части; при наличии обеих версий выбирается вариант с баннером.
- Ручное заполнение очереди, WATCH с интервалом на профиль, окна публикаций и IANA-часовой пояс. Один ролик на окно; время внутри окна выбирается случайно. WATCH работает, пока приложение открыто.
- Отдельные состояния загрузки R2, запроса Buffer, планирования и подтверждённой публикации. В `posted` файл переносится после статуса `sent` от Buffer, а не по наступлению времени.
- Сохранение намерения отправить пост **до** запроса Buffer. При потере ответа — сверка канала и блокировка повторной отправки. SHA-256 блокирует одинаковое содержимое под разными именами в истории одного профиля.
- Шаблоны описаний, хештеги и предпросмотр; сезон и серия нужны только при использовании соответствующих переменных.
- До 40 баннеров: наложение на движущееся видео либо прежняя вставка со стоп-кадром. Координаты, область размера, прозрачность, время, длительность, схема расположения, шаблоны, пакетная обработка, прогресс и отмена.
- Нарезка по заданной длительности с названиями `часть 1.mp4`, `часть 2.mp4` или собственным шаблоном, начальным номером и общей нумерацией нескольких исходников. Баннеры можно добавить в каждую часть за тот же проход кодирования либо отключить. Последний короткий остаток сохраняется по выбору.
- Передача результатов монтажа в `ready` выбранных профилей без автоматической публикации. Исходные видео не изменяются; повторный экспорт получает новое имя.
- Статистика только из официальных полей Buffer. Отсутствующие метрики отображаются как «—»; показатели не генерируются и не заменяются другими.

## Первый запуск на Windows

1. Распакуйте ZIP в отдельную папку и запустите **JetVideo.exe**. Готовая сборка работает на Windows 10/11 x64 без установки Python.
2. В окне первого запуска нажмите **Да**, чтобы создать рабочую папку внутри `JetVideo Data` рядом с программой. Нажмите **Нет**, чтобы выбрать другую папку. Для работы только с видео отмените выбор папки после **Нет**.
3. В ZIP уже есть `tools/ffmpeg.exe` и `tools/ffprobe.exe`. После распаковки JetVideo найдёт их автоматически. Оставьте `JetVideo.portable` рядом с EXE, чтобы эта копия хранила собственные настройки.
4. Для публикаций откройте «Публикации» → «Расписание» → «Папки ready / scheduled / posted», если хотите использовать свои каталоги видео. Выберите отдельные папки для каждого профиля. Существующие видео при смене пути остаются в прежних папках.

В установщике можно выбрать каталог установки. Настройки, очередь и медиа хранятся отдельно. [Условия сторонних компонентов](THIRD_PARTY_NOTICES.md).

## Нарезка видео

1. В «Монтаж и нарезка» нажмите «Добавить видео» или «Из публикаций», если исходник уже лежит в папке `ready` аккаунта. Выберите «Нарезать на части».
2. Задайте длительность и шаблон. Например, `02:00` и `часть {part}` дадут `часть 1.mp4`, `часть 2.mp4` и так далее. «Начальный номер» позволяет продолжить серию, а `{part:03d}` выводит номер с нулями. Для нескольких исходников нумерация продолжается в порядке списка.
3. В блоке «Баннеры» выберите «Без баннеров», «Наложение баннеров» или «Стоп-кадр с баннерами». При включённых баннерах нажмите «Добавить баннер» и задайте файл и время. `00:00:30` означает 30-ю секунду **каждой части**. Наложение сохраняет длительность части, стоп-кадр добавляет время вставки.
4. Для последнего короткого ролика оставьте флажок «Сохранять последний короткий фрагмент». Баннер, время которого выходит за его границы, пропускается. Проверьте журнал, если баннера в коротком ролике нет.
5. Укажите папку и нажмите «Начать нарезку». По завершении нажмите «Открыть папку» или «Передать в публикации», чтобы выбрать аккаунт для передачи готовых видео в `ready`.

[Примеры нарезки и шаблонов имён](docs/SPLITTING.md).

## Настройка Buffer и R2

Откройте **Публикации → Подключения**. Нажмите **?** справа от поля, чтобы узнать, где взять значение. Полные инструкции со скриншотами доступны здесь. [Ключ Buffer](docs/BUFFER_SETUP.ru.md) · [Настройка Cloudflare R2](docs/R2_SETUP.ru.md)

В «Публикации» → «Подключения» заполните:

| Поле | Значение |
| --- | --- |
| Buffer API Key | Личный ключ из Buffer Settings → API |
| R2 Endpoint | HTTPS S3 endpoint вашего аккаунта R2 |
| R2 Access Key ID / Secret Access Key | S3-совместимые ключи для выбранного bucket |
| R2 Bucket | Имя bucket |
| R2 Public URL | Публичный HTTPS-домен bucket без имени файла |

Ключи сохраняются локально в `.env` выбранной рабочей папки. Пример без значений: [.env.example](.env.example). Не передавайте `.env`, историю и рабочую папку в репозиторий или отчёты об ошибках. Резервные копии содержат личные данные. Ключи в локальном `.env` не шифруются; доступ к файлу нужно защищать средствами учётной записи Windows.

В Cloudflare создайте bucket и S3-ключ с необходимыми правами чтения/записи/удаления, ограниченными этим bucket. Для Buffer нужен стабильный прямой публичный URL. Содержимое R2 с публичным доступом доступно получателям URL; приватный S3 endpoint не является публичной ссылкой на видео. Пользователь сам включает публичный доступ или настраивает свой домен. Внешние сервисы имеют собственные тарифы, квоты и условия использования.

Откройте «Аккаунты». Выберите существующий профиль или нажмите «Новый аккаунт». Нажмите «Привязать Buffer» → «Найти в Buffer», выберите канал TikTok и нажмите «Сохранить привязку». Повторите для каждого канала. При смене канала с существующей историей создайте новый профиль. «Архив / восстановить» скрывает неиспользуемый профиль из рабочего списка, а «Удалить профиль» оставляет его видео на диске и уже запланированные посты в Buffer.

После привязки канала нажмите «Проверить подключения». JetVideo обращается к Buffer, создаёт небольшой временный объект в R2 и проверяет, открывается ли он по публичной ссылке. После проверки программа пытается удалить объект. Пост не создаётся.

Документация, сверенная 20 ноября 2026 года: [аутентификация Buffer](https://developers.buffer.com/guides/authentication.html), [создание видео](https://developers.buffer.com/examples/create-video-post.html), [публичное размещение медиа](https://developers.buffer.com/guides/hosting-media.html), [расписание и статусы](https://developers.buffer.com/guides/posts-and-scheduling.html), [S3 API R2](https://developers.cloudflare.com/r2/api/s3/api/).

## Первая публикация

1. Выберите профиль и откройте **Расписание**. Нажмите **Часовой пояс** и выберите город или регион из списка. В поиске можно написать `Kyiv`, `New York` или `UTC`. Задайте окна публикаций и лимит очереди, затем нажмите **Сохранить расписание**.
2. Скопируйте один тестовый ролик в его `ready` или используйте «Добавить видео». Завершите копирование и подождите время готовности файла (по умолчанию 15 секунд). На Windows файл с открытым дескриптором записи не загружается.
3. Настройте текст публикации и проверьте, как он выглядит. [Подписи и теги](#captions-and-tags)
4. На «Главной» нажмите «Предпросмотр», чтобы увидеть план без загрузки. Затем «Текущий аккаунт» заполняет очередь после подтверждения. «Все аккаунты» запускает обработку для всех активных профилей. Кнопка «Включить WATCH» проверяет очередь повторно по расписанию, пока приложение открыто.
5. Проверьте пост непосредственно в Buffer и TikTok. «Сверить Buffer» обновляет состояния без создания новых постов. По подтверждённому `sent` видео перемещается в `posted`.

Откройте **Историю публикаций** с главного экрана или из бокового меню. Найдите запись по имени файла или номеру части. Дважды нажмите на строку или выберите её и нажмите **Подробности**, чтобы увидеть полное имя файла, статус, дату и номер части.

### Неоднозначный результат и восстановление

`uploaded` означает только загрузку в R2; `scheduled` — принятие в очередь; `sent` — подтверждение публикации API. `uncertain` означает, что запрос мог быть принят, но результат неизвестен. Такой ролик автоматически повторно не отправляется, а его R2-копия сохраняется.

Остановите WATCH и нажмите «Сверить Buffer». Программа загружает все страницы канала и сопоставляет сохранённые описание, канал и время намерения. Найденная однозначная запись восстанавливается; неполная выгрузка или несколько совпадений оставляют блокировку. При отсутствии записи **вручную проверьте TikTok и Buffer**. Отсутствие в API само по себе не доказывает, что публикации не было: Buffer ограничивает доступную историю. Только после проверки используйте «Вернуть в ready» и отдельно повторите заполнение очереди. История возврата сохраняется.

Не удаляйте `state.json` для исправления ошибок: это снимает защиту от повторов. Повреждённая история останавливает работу и требует восстановления из резервной копии. Идентичность по хешу применяется к отправкам этой версии; старые записи без хеша сохраняют защиту по номеру/ID поста.

## Подписи и теги

Откройте **Публикации → Подписи и теги** для нужного профиля. Слева задаётся текст, справа — наборы хештегов.

### Шаблоны текста

Для обычного видео напишите готовое описание или вставьте `{filename}`, чтобы взять имя файла без расширения. Для нарезки используйте `{part}`. Например, для файла `часть 7.mp4` шаблон `Смешной момент · Часть {part}` даст «Смешной момент · Часть 7».

В поле **Шаблоны текста** нужен хотя бы один вариант. Если вариантов несколько, поставьте `---` на отдельной строке между ними. Пример для двух шаблонов с тегами:

```text
Смешной момент · Часть {part}
{hashtags}
---
Подборка · Часть {part}
{hashtags}
```

JetVideo распознаёт номер в названиях вроде `7.mp4`, `7_with_ad.mp4`, `часть 7.mp4`, `частина 7.mp4` и `Part 7.mp4`. Для произвольных названий подходит `{filename}`. Переменные `{season}` и `{episode}` подставляют сезон и серию. Перед их использованием укажите и сохраните диапазоны частей в **Сезоны и серии**. Например, части с 1 по 3 можно отнести к сезону 1, серии 2.

### Наборы хэштегов

В **Наборах хэштегов** пишите теги с `#` и разделяйте пробелами. Каждая строка — отдельный набор. Добавьте `{hashtags}` в шаблон в том месте, где должны появиться теги.

```text
#нарезка #смешно
#видео #подборка
```

Если есть несколько шаблонов и наборов, JetVideo выбирает по одному случайно и независимо. Чтобы публиковать без тегов, оставьте правое поле пустым.

Нажмите **Предпросмотр описания**, укажите имя файла и тестовый номер части, например `7`. Если всё выглядит как нужно, нажмите **Сохранить подписи и теги**. Если вы ещё настраиваете первую публикацию, проверьте подключение к сервисам. [Настройка Buffer и R2](#connections)

## Монтаж и баннеры

1. Для баннера на целом видео откройте «Монтаж и нарезка», выберите «Целое видео с баннерами» и добавьте исходники.
2. Нажмите «Добавить баннер». Поддерживаются видео и изображения PNG/JPEG. Задайте время от начала исходного видео, положение, размер, непрозрачность и длительность. Для изображения длительность по умолчанию составляет 3 секунды. Схема показывает положение в кадре 9:16, а проценты применяются к реальному размеру исходника.
3. В «Настройки» можно выбрать качество, способ вписывания, хромакей и звук для вставок со стоп-кадром. Выберите папку результата и нажмите «Создать видео».

«Наложение» поддерживает несколько одновременных баннеров, сохраняет длину видео и исходный звук; звук баннеров в этом режиме не добавляется. «Стоп-кадр» сохраняет прежнюю логику: исходник приостанавливается, баннер добавляет время, звук рекламы можно включить. Для одного шаблона выбирайте один режим; смешивание режимов отклоняется. Время стоп-кадра должно быть внутри ролика, с запасом одного кадра от краёв.

Кнопки «Сохранить шаблон» и «Загрузить шаблон» находятся в блоке «Баннеры». Шаблон хранит пути к баннерам, поэтому после переноса на другой компьютер проверьте их расположение. «Отмена» завершает кодирование и оставляет готовые файлы. «Журнал» содержит детали обработки и ошибки. «Передать в публикации» копирует готовые результаты в `ready` выбранных аккаунтов. Саму публикацию запускают из раздела «Публикации».

## Статистика

В «Публикации» → «Статистика» нажмите «Обновить все». Доступность и свежесть показателей определяет Buffer. Символ «—» означает отсутствие данных, а звёздочка у суммы указывает на неполную выборку. [Описание метрик Buffer](https://developers.buffer.com/guides/post-metrics).

Для сверки очереди откройте «Синхронизация» и нажмите «Проверить все аккаунты». Результаты можно посмотреть перед применением статусов. Для действий с одним профилем используйте «Сверить Buffer» на «Главной».

## Данные, обновления и журнал

Для совместимости с предыдущими версиями JetVideo хранит путь к рабочей папке и язык в `%LOCALAPPDATA%\JOJO BOT`. Рабочая папка по умолчанию — подкаталог `data`, журнал — `logs` (ротация примерно после 2 MB). Настройки редактора сохраняются в `%APPDATA%\VideoAdInserter\preferences.json` для совместимости с прежней версией. Для выбранного другого workspace конфигурации и очередь остаются там; видео находятся в выбранных пользователем папках. EXE и установщик не содержат аккаунтов и не заменяют эти файлы.

Закройте старую программу и WATCH перед обновлением. Скопируйте рабочую папку и настройки редактора в частную резервную копию, замените EXE и проверьте пути/каналы. Можно подключить прежнюю рабочую папку через «Журнал действий» → «Подключить папку». Опция переноса workspace копирует его в новое место и оставляет исходник. Новая версия не импортирует личные данные в публичный каталог исходников.

## Частые проблемы

| Проблема | Что проверить |
| --- | --- |
| Пустые настройки | Заполните подключения, затем привяжите TikTok-канал |
| 401 / 403 Buffer | Личный API-ключ, его доступ и подключение канала |
| 429 / лимит | Дождитесь снятия лимита сервиса; проверьте тариф и очередь |
| Нет ответа после отправки | Сверьте Buffer; не сбрасывайте историю и не повторяйте вслепую |
| Файл пропущен | Завершено ли копирование, возраст файла, история, одинаковый SHA-256 |
| Неправильный часовой пояс | Используйте IANA-имя, например `Europe/Kyiv`; неизвестная зона блокирует планирование |
| R2 работает, URL недоступен | Публичный домен, прямой HTTPS URL, настройки bucket |
| Ошибка JSON истории | Восстановите проверенную резервную копию при остановленном WATCH |
| Нет FFmpeg / FFprobe | Распакуйте полный ZIP с папкой `tools` или выберите FFmpeg в «Настройки» |
| Вставка вне ролика | Уменьшите время появления либо выберите подходящие исходники |
| Папка данных недоступна | Подключите диск и исходный workspace; пустая история не создаётся взамен автоматически |

## Разработка и сборка

Для сборки релиза использован CPython 3.14.10 x64 с Tkinter. `requirements.txt` фиксирует зависимости приложения, а `requirements-build.lock` — зависимости сборки и тестов.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.lock
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe studio.py
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean "JetVideo.spec"
& '.\dist\JetVideo.exe' --smoke-test verification/frozen-smoke.json
```

Автоматический вариант — `build_windows.bat`; необязательный установщик — `build_installer.bat` при установленном Inno Setup 6. GitHub Actions собирает артефакт без ключей сервисов и без автоматической публикации релиза. FFmpeg-тесты выполняются, если инструменты доступны в PATH; иначе явно пропускаются.

## Верхние кнопки

- **?** открывает справку. Клавиша **F1** делает то же самое.
- **$** обозначает добровольную поддержку разработчика. Кнопка пока неактивна.
- Значок гарнитуры предназначен для страницы техподдержки. Кнопка пока неактивна.
- Значок глобуса переключает язык между русским, английским и украинским.
