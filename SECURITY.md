# Личные данные и отчёты об ошибках

Не прикладывайте `.env`, config.json с реальными каналами, state.json, profiles.json, кэш статистики, recovery, рабочие папки или личные видео к публичным issues. Перед отправкой журнала проверьте имена аккаунтов, подписи, пути и URL. Программа маскирует известные ей ключи в журнале, но это не заменяет проверку содержимого.

`release_security.py` проверяет публичную папку по опасным именам и шаблонам ключей; при наличии локального Git проверяет также blobs всех refs и reflog. Проверка эвристическая, не гарантирует обнаружение любого секрета. `.gitignore` не очищает уже закоммиченную историю. Перед публичной отправкой дополнительно просмотрите список отслеживаемых файлов и историю и используйте секрет-сканер хостинга.

Если секрет оказался в публичном Git/архиве/журнале, сначала отзовите и замените соответствующий Buffer API Key и/или пару R2 Access Key ID + Secret Access Key. Затем очистите опубликованные файлы и историю; одного удаления текущего `.env` недостаточно. При подготовке этой версии секреты в публичные сервисы не отправлялись.

Отдельный контрольный аудит 20 ноября 2026 года обнаружил ключи только в прежних локальных настройках; совпадений с их значениями в подготовленном публичном исходном наборе не было. Git-каталоги в исходном проекте не обнаружены. Личные настройки и история сохранены в прежних каталогах и не входят в дистрибутив.
